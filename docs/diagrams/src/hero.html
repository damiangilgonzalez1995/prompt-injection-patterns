Prompt Injection Patterns

Six architectural defences for LLM agents · built on LangGraph
the defence lives in the graph state, not in the prompt
An injection hides inside data the agent must read. Each pattern denies it a different power, at a different stage of the agent loop.

The six patterns  ·  one guard per stage
Decide
01

Action-Selector

fixed action list

output is one label from a closed enum — a bad action cannot be expressed

Plan
02

Plan-Then-Execute

frozen plan

plan fixed before untrusted data is read — it cannot be rewritten

Perceive
03

LLM Map-Reduce

map-output sanitizer

one isolated worker per item, typed reduce — blast radius of one

Perceive
04

Dual LLM

privileged + symbolic memory

the deciding model never sees untrusted text — only typed handles

Act
05

Code-Then-Execute

execution sandbox

AST allowlist + sandbox before the code runs — no un-allowed calls

Remember
06

Context-Minimization

context pruner

untrusted content pruned from history after use — lives one turn

How to read it
1
Action-Selector guards Decide — the model can only pick from a list you wrote.
2
Plan-Then-Execute guards Plan — the recipient and steps are bound before reading data.
3
Map-Reduce guards Perceive (many docs) — isolate each, aggregate only typed fields.
4
Dual LLM guards Perceive — quarantine reader; privileged model sees typed handles only.
5
Code-Then-Execute guards Act — vet the program with an allowlist, run it sandboxed.
6
Context-Minimization guards Remember — expire untrusted content so it fires once.
